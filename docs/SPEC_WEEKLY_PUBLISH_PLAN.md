# 주간 발행 요일 계획 (blog · blogs) — 2026-11-10

## 배경
AdSense가 세 사이트 모두를 "가치 없는 콘텐츠"로 반려했다. GSC 기준 최근 90일 클릭은 geniezst.com 32회, pockemoney.com 5회였다. 하루 1편 AI 자동 발행은 대량 생성 콘텐츠로 보일 위험이 크다. 그래서 발행 빈도를 줄인다.

## 요구사항
1. blog(geniezst.com)와 blogs(pockemoney.com)는 각각 **주 2~3회**, 랜덤 요일에 발행한다.
2. **두 사이트가 같은 날 발행하지 않는다.**
3. 발행 요일의 시각 범위는 기존과 같다 (blog 18:50~19:20, blogs 18:15~18:45 KST 랜덤).
4. 데몬을 재시작해도 그 주의 계획이 바뀌지 않는다.

## 설계
- 공용 모듈은 `scripts/lib/weekly-publish-plan.mjs`다. 두 저장소에 **같은 사본**을 둔다 (`cmp`로 확인).
- 주 단위는 ISO 8601 주(월~일)다. 주차 ID(예: `2026-W46`)는 KST 날짜 문자열을 기준으로 UTC 계산한다.
- 계획은 `sha256(PLAN_SALT + ':' + 주차 ID)`로 정해진다.
  - 0~6 요일을 Fisher–Yates로 섞는다.
  - 앞의 2~3개를 blog가, 그다음 2~3개를 blogs가 가진다. 그래서 두 사이트의 요일은 구조적으로 겹칠 수 없다.
- 결정적 계산이라 두 데몬이 상태를 공유하지 않아도 계획이 일치한다.
- 상태 파일에는 기록용 `weekly_publish_plan`만 남긴다. 예전 `weekly_skip_config`는 처음 실행될 때 삭제된다.
- 러너의 `checkOrUpdateWeeklySkip()`는 `{ is_rest_day, publish_days, publish_day_names, day_name, ... }`를 돌려준다.
  - 데몬 루프와 CLI `evening`은 비발행일에 건너뛴다.
  - CLI는 `--force`를 주면 우회한다.
- 텔레그램은 매주 계획이 처음 기록될 때 1회만 알린다. blogs가 매일 보내던 휴식 알림은 없앴다.
- 실패 재시도(같은 날 30분 뒤, 최대 2회)는 그대로다. 발행일에 2회 모두 실패하면 그 주 발행은 1회 줄어든다.

## 검증 (2026-11-10)
- 2026-01-01부터 10년치를 확인했다.
  - 같은 날 두 사이트가 모두 발행일인 경우는 0건이었다.
  - 주당 2회와 3회가 거의 반반이었다.
  - 요일 분포도 고르게 나왔다.
- 패치된 `checkOrUpdateWeeklySkip` 함수를 스텁 환경에서 11/09~11/22 동안 실행했다. 계획이 같았고, 저장과 알림은 주 1회만 일어났다.
- 두 러너 모두 `node --check`를 통과했다.
